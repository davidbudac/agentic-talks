The hook

Illustrative trace: a passing test is evidence for that case. Review the diff and relevant edge cases before accepting the change.

Core · chatbot vs agent

A chatbot answers. An agent acts.

Chatbot — the one you know

You ask → it tells you what to do → you open the files, run the commands, paste the errors back… and repeat.

Agent

You ask → it does the work itself — reads the files, runs the commands, checks the result → you review at the end.

The model proposes actions. The harness executes permitted tools. Together, repeating this process, they form an agent.

One example throughout: an invoice total that is missing VAT.

Harness · what runs where

Model in the cloud, harness on your machine

You talk to the agent. Claude Code is the harness — it runs locally with your files & terminal, and loops with the model in the cloud (which stays stateless). The agent isn't a separate thing — it's that loop.

Agent · the loop

An agent is a loop

  1. Propose: the model chooses the next action.
  2. Run: the harness executes it under the configured permissions.
  3. Observe: the result returns as context for the next step.
  4. Check: stop when the task is verified, or ask when blocked.

In a live run or a finished transcript, point to one tool call and its result. That is one lap of the loop.

Thinking · how it works

The model thinks before it answers

  • Reasoning gives the model room to work through intermediate steps before answering or acting.
  • More effort can help a difficult diagnosis; it also takes more time and tokens.
  • For the invoice task, verify the VAT rule and run the test. A plausible explanation alone is not evidence.

Visible thinking may be a summary. Judge the result and the checks, not how convincing the narration sounds.

Context · what it is

Context = the model's short-term memory

  • Context contains the instructions, conversation and tool results supplied for this call.
  • The context window is the maximum capacity. Its size depends on the model and configuration.
  • Supply the relevant test and invoice code. An unread file cannot guide the model through this request.
Context

More context is not always more useful

Useful context

The failing test, the VAT rule and the code path that computes the total.

Distracting context

Old tasks, duplicate file dumps and unrelated logs that obscure those facts.

Watch for ignored requirements, repeated work and missed evidence. There is no universal percentage at which quality fails.

Context

Cheaper reuse and shorter context

Caching

Reuses computed state for a matching prefix. It can reduce processing cost and latency; the content is still input.

Compaction

Replaces older material with a summary. It frees room, but details omitted from that summary may be lost.

For the invoice task, preserve the VAT rule, failing test, attempted changes and verification command.

Context · sub-agents

Sub-agents keep the main context clean

  • Delegate a focused investigation, such as finding every place invoice totals are calculated.
  • The helper’s intermediate tool output stays in its own working context. Ask for a concise result with evidence.
  • A fresh subagent needs a self-contained task. A conversation fork can inherit the existing history.
Permissions

Decide what the agent may touch

01

Scope the work

Allow the project files and test commands needed for the task.

02

Keep approval points

Ask before destructive actions, access changes or publishing outside the task.

03

Contain mistakes

For unattended experiments, restrict filesystem, network and credentials in an actual sandbox.

A separate folder or Git branch protects neither credentials nor the rest of the machine. Check the configured boundary.

Project knowledge

Teach it the rules it cannot infer

# CLAUDE.md — invoice project - Run invoice checks with: python -m unittest - VAT rates come from the order record. - Do not replace the tests to make a fix pass. - Ask before changing the stored invoice schema.

Keep standing rules short. Use the instruction-file convention supported by your harness, such as CLAUDE.md or AGENTS.md.

Project knowledge

Save a repeatable check as a skill

invoice-check/ SKILL.md when to run + how to verify scripts/ optional deterministic checks references/ VAT and rounding rules

Skill: a reusable procedure loaded when relevant. Plugin: a way to distribute a toolkit to a team.

Reaching out · MCP

MCP = "USB-C for agents"

  • MCP standardizes how a supported client discovers and calls tools exposed by a server.
  • Example: read the issue describing the invoice bug, then propose an update with verification evidence.
  • Each integration still needs compatible support, authentication and scoped permissions.
