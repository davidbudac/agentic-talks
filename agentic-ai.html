03
Terms · the basics

Three building blocks

Model

The brain. A stateless function: text in → text out. All the intelligence, none of the action.

Harness

The body & environment. The program around the model that holds context and runs tools.

Agent

Model + harness that actually does things — calling tools in a loop until the job is done.

The one line to remember: "agent" means it does something. The model alone only predicts text.

04
Model · the brain

The model is stateless

text → text

Give it input, get output. Between calls it remembers absolutely nothing.

  • Under the hood it just predicts the next token — no database, no memory of "you".
  • It holds all the intelligence but can't do anything by itself — it can't run a command or read a file.
  • Every call starts from zero. Anything it should know must be sent in again.
05
Model · example

"Stateless" in practice

There is no "conversation" on the model's side. Each API call re-sends the whole history as one flat list of messages:

# Turn 3 of a chat — the model is handed ALL prior turns again messages = [ {role:"user", content:"My name is David."}, {role:"assistant", content:"Nice to meet you, David."}, {role:"user", content:"What's my name?"} ← needs turn 1 re-sent ]

Remove the first message and the model has no idea who you are. The "memory" lives in the request, not the model.

06
Harness · the body

The harness does the work around

  • Holds the conversation and assembles the context it sends to the model on every turn.
  • Executes tool calls — reads/writes files, runs shell commands, calls APIs, searches the web.
  • Runs the loop, asks for permissions, and manages caching & compaction behind the scenes.
Claude Code & Codex are harnesses

Model alone = a chat box. Model + harness + tools = an agent. Same model, different harness → very different capabilities.

07
Harness · example

What one turn really sends

EXAMPLE — a single Claude Code prompt
# The harness builds this context for the model, every turn: 1. system prompt # who you are, available tools 2. CLAUDE.md # project rules & conventions 3. conversation so far # every previous message 4. tool results # files read, command output 5. your new message "fix the failing test"

You typed one line. The harness turned it into thousands of tokens of context — and will do so again on the next turn.

08
Agent · the loop

An agent is a loop

The model proposes an action, the harness runs it, the result goes back to the model. Repeat until done.

1Model proposes
an action (tool call)
→
2Harness runs it
→
3Result fed
back to model
↻
4Repeat until
the task is done

This loop is the whole "magic" of agentic AI — no magic, just disciplined repetition over many small tool calls.

09
Agent · worked example

"Fix the failing test" → the loop

▸ run_tests() → FAIL: test_invoice expected 121, got 100 ▸ read_file(invoice.py) → sees VAT is never applied ▸ edit_file(invoice.py) → adds total *= 1.21 ▸ run_tests() → PASS ✓ ▸ done — 4 tool calls, no human in between

Each step is one trip through the loop. The model never "ran" anything itself — the harness did, and reported back.

Models · picking a tier

Which tier when?

Large · Opus

Hard reasoning, tricky multi-file refactors, architecture. Slow & expensive — reach for it when it matters.

Medium · Sonnet

The daily driver. Most coding & agent work. Often beats last gen's flagship at a fraction of the cost.

Small · Haiku

High-volume, simple, latency-sensitive: classification, quick edits, sub-agent grunt work.

Example: let a Haiku sub-agent grep 200 files and summarize, then hand the summary to Opus for the actual design decision — cheap legwork, expensive thinking only where needed.

14
Pricing · plan vs API

Subscription vs API

Subscription

A flat monthly fee for a person using the app/CLI. Simple, capped by usage limits. Best for everyday work.

API

Pay per token (input + output). No cap, scales to production. Best for building integrations.

Why tokens matter: a token ≈ ¾ of a word. A long agent session can read your files dozens of times — and on the API you pay for every re-read. That's exactly why caching (slide 18) exists.

15
Context · what it is

What is context?

  • Everything the model "sees" in one call: system prompt, CLAUDE.md, chat history, files, tool output.
  • Measured in tokens (≈ chunks of words).
  • The context window is the max size — typically 200K tokens (≈ 500 pages), up to 1M on top models.
The only memory

Context is the model's entire working memory. If it isn't in the context, it does not exist for the model.

16
Context · the "stupidity threshold"

Fuller context = dumber model

"Context rot"

Chroma tested 18 frontier models: every one gets worse as input grows — even when the answer is right there.

  • Lost in the middle (Stanford): models recall the start & end well, but miss facts buried in the middle.
  • Rule of thumb: keep the window well under half full. The "40% threshold of stupidity" is folklore, not an exact law — but it points the right way.
  • A bigger window is not a fix. Curation beats capacity.
17
Context · measuring it

Watch your context usage

EXAMPLE — Claude Code status line
claude-opus-4-8 context: 38% (76k / 200k) $0.42
  • Most harnesses show live % used — keep an eye on it.
  • Climbing past ~40–50%? Quality starts to slip. Time to trim or restart.
  • Habit: finish a task, then start a fresh chat rather than dragging a bloated one onward.
18
Context · caching

Caching: don't re-read for free

Stable parts of the context (system prompt, CLAUDE.md, files) can be cached, so repeat calls are far cheaper and faster.

Cache write

1.25× normal input price — a small one-time premium to store it.

Cache read

0.10× input price — a 90% discount on everything reused.

Lifetime

~5 min by default (1 hr extended). Each hit resets the timer.

Without caching, the model re-reads the entire context every step — that's the cost (and latency) caching removes.

19
Context · compaction

Compaction: summarise & reclaim

  • When the window fills, the harness summarises older turns into a short recap and drops the raw text.
  • You free up space to keep working without starting over.
  • Trade-off: detail is lost. Anything not in the summary is forgotten — so the summary must keep what matters.
~120k → ~15k

A long session gets compacted into a tight summary, and the loop continues with room to breathe.

20
Context · sub-agents

Sub-agents keep the main context clean

  • A sub-agent is a separate agent with its own fresh context for one sub-task.
  • The main agent delegates → the sub-agent does the messy work → returns only the conclusion.
  • The main conversation stays clean, and several sub-agents can run in parallel.
Delegate & collect

Example: "search these 200 files" reads 80k tokens inside the sub-agent — the main chat receives a 200-token answer.

21
Safety · permissions

Safety through permissions

Default · ask

The agent asks first before any sensitive action (write a file, run a command). Safest.

Auto · accept edits

Pre-approve a class of actions (e.g. file edits) so it won't interrupt on routine steps.

Bypass · "YOLO"

Asks for nothing. Fast, but it can run any command — only in a sandbox.

Both Claude Code and Codex ship these modes (Codex calls them suggest / auto-edit / full-auto). More freedom demands more isolation.

22
Safety · bypass mode

When is "YOLO" OK?

  • Only where a mistake can't hurt: a container, a throwaway VM, an isolated git worktree, or CI.
  • Never bypass on your main machine with prod credentials and no backup.
  • Remember: an agent reads files and the web — a malicious instruction in either can hijack a no-questions-asked agent.
Freedom ∝ isolation

The rule: the more autonomy you grant, the more walls you put around it. Speed is worth it — recklessness isn't.

23
Recap · stateless again

The model is the guy from Memento

Remembers nothing

Every interaction, the model has no idea what we discussed. No "yesterday", no "a minute ago".

  • Every call re-reads the whole context (unless it's cached).
  • All "memory" is an illusion the harness maintains — not the model.
  • So: how do we give it durable memory without stuffing the window?
24
Memory · CLAUDE.md

Memory that survives sessions

EXAMPLE — CLAUDE.md in your repo root
# CLAUDE.md — injected into every prompt automatically - Package manager: pnpm (never npm) - Run tests with: make test - API code lives in /services; never edit /generated - House style: small functions, no comments unless asked
  • CLAUDE.md — read at the start of every session; your standing instructions & conventions.
  • Memory files — durable notes the agent saves and reloads later (some harnesses do this automatically).
25
Memory · skills & plugins

Skills & plugins

  • Skill = a folder with a SKILL.md (a name + description, plus instructions, scripts, resources).
  • Progressive disclosure: the agent only reads a skill's full instructions when a task matches — so you can keep dozens on hand for almost no context cost.
  • Plugins bundle and distribute skills, commands & MCP servers across a team.
Just-in-time know-how

Example: a "make-slides" skill stays dormant until you ask for a deck — then its full playbook loads.

26
Reaching out · other systems

Touching other systems

API

Services called programmatically over HTTP. The agent sends a request, gets structured data back.

CLI

Command-line tools the agent runs just like a human in a terminal (git, gh, kubectl…).

MCP

Model Context Protocol — an open standard to plug tools & data into any agent.

CLIs & APIs already exist everywhere — the agent just uses them. MCP is the newer, agent-native way to connect.

27
Reaching out · MCP

MCP = "USB-C for agents"

  • Anthropic's open standard (Nov 2024). Solves the N×M problem: stop writing a custom connector for every tool × every app.
  • You run an MCP server once; any MCP-aware agent can use it. Thousands now exist.
  • It exposes tools (actions), resources (data) and prompts over a simple protocol.
EXAMPLE — connected MCP servers
GmailGoogle CalendarDriveGitHubPostgresSlack

"Find my next meeting with the audit team and draft a follow-up" — Calendar + Gmail, one agent, no custom glue code.

28
Summary

What to take away

  • Model = a stateless brain · harness = the body & memory · agent = the loop that does things.
  • Mind the context — quality rots as it fills; caching, compaction & sub-agents are how we cope.
  • Permissions are your safety net; bypass mode only inside isolation.
  • CLAUDE.md, memory, skills, MCP = how we give a forgetful model durable knowledge & reach.
